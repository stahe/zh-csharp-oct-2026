    7. 委托、Lambda 和事件

    在 2008 年的课程中，本章紧接在 Windows Forms 图形用户界面一章之后：事件首先在按钮和窗体的上下文中介绍，然后学生再学习如何在自己的类中创建事件。图形用户界面一章已从本版课程中删除。因此，我们直接从支撑整个机制的概念开始：委托，即引用一个或多个方法的对象。所有示例都是控制台程序。

    在过去二十年中，委托已成为该语言中使用最广泛的工具之一。借助 Lambda 表达式 （C# 3），编写委托变得简单得多，我们在第 5 章用 LINQ 时已经用过它，只是没有深入细节：[Where(n => n > 5)] 把一个 Lambda（也就是一个委托）传递给方法 [Where]。本章解释这种语法背后的原理。本章最后讲解 事件，它们同样基于委托。.NET 的图形用户界面（Windows Forms、WPF、.NET MAUI）以及 Web 框架都基于这一机制：按钮点击或 HTTP 请求的到达会被通知给已订阅的方法。

    本章的程序是位于 [07-delegates] 文件夹中的单文件应用程序。它们使用 [dotnet run delegates-NN.cs] 运行。

    7.1. 预定义的委托类型

    7.1.1. 委托的概念

    委托类型 描述方法的一个模型（也称为原型或签名）：其参数的类型和返回值的类型。委托类型的变量随后可以引用任何符合该模型的方法并执行它。

    .NET 框架定义了许多委托类型。最古老的是 [EventHandler]，本章末尾将讨论的所有事件都使用它。它的定义如下：

    1
    public delegate void EventHandler(object? sender, EventArgs e);

    关键字 [delegate] 使 [EventHandler] 成为委托类型。该类型表示一种方法模式：

    • 其第一个参数是类型为 [object?] 的对象（触发事件的对象，可能为 [null]）；
    • 其第二个参数是类型为 [EventArgs] 的对象（有关事件的信息）；
    • 不返回任何结果（[void]）。

    符合 [EventHandler] 所定义模型的方法可以如下：

    1
    static void Display(object? sender, EventArgs e) { ... }

    要创建引用该方法的 [EventHandler] 类型对象，可以这样写：

    1
    EventHandler handler = new EventHandler(Display);

    或者，更简单地：

    1
    EventHandler handler = Display;

    在第二种写法中，方法名 [Display] （一个 方法组，因为一个方法可以有多个重载）被编译器自动转换为 [EventHandler] 对象：这就是方法组转换，自 C# 2 起就已可行。编译器会从 [Display] 的各个重载中选择与委托签名相匹配的那一个。然后委托像方法一样被执行：[handler("program", EventArgs.Empty)]。

    7.1.2. 泛型委托 Func、Action 和 Predicate

    在泛型出现之前（C# 2），必须为每种方法签名定义一个委托类型。如今，框架提供了泛型委托类型，几乎可以满足所有需求：

    委托类型
    所引用的方法
    [Action]
    无参数，无返回值：[void M()]
    [Action<T1, ..., T16>]
    1 到 16 个参数，无返回值：[void M(T1 p1, ...)]
    [Func<TResult>]
    无参数，有一个返回值：[TResult M()]
    [Func<T1, ..., T16, TResult>]
    1 到 16 个参数，返回值的类型为 [TResult] （始终是最后一个类型参数）
    [Predicate<T>]
    一个参数，返回布尔值：[bool M(T p)]
    [Comparison<T>]
    两个相同类型的参数，返回整数：[int M(T x, T y)]

    [Predicate<T>] 和 [Func<T, bool>] 描述的是同一个签名，但它们是两个不同的类型：[Predicate<T>] 诞生于 .NET 2，被 [List<T>] 和 [Array] 的方法（[FindAll]、[RemoveAll]、[Exists]……）使用，而随 .NET 3.5 引入的 LINQ 则使用 [Func<T, bool>]。

    7.2. 定义委托类型

    预定义类型通常已经足够，但你也可以定义自己的委托类型。语句：

    1
    public delegate int Operation(int n1, int n2);

    定义了一个名为 [Operation] 的类型，它代表一个接受两个整数并返回一个整数的方法模板。与 [Func<int, int, int>] 相比，类型 [Operation] 的名称描述了其用途，其参数也有名称（[n1]、[n2]），开发工具会显示这些名称。

    类型为 [op] 的变量 [Operation] 用于存储与 [Operation] 模型相对应的方法 列表：这称为 多播委托。

    • 类型为 [f] 的方法通过 [op = new Operation(f)] 或更简单的 [op = f] 存储到变量 [op]中；
    • 要将方法 [g] 添加到已注册的方法列表中，写作 [op += g]；
    • 要移除已注册的方法 [h]，写作 [op -= h]；
    • 语句 [n = op(n1, n2)] 会按注册顺序执行 [op] 中注册的所有方法，使用参数 [n1] 和 [n2]。返回的结果 [n] 是最后一个被执行的方法的结果。

    2008 年的课程指出无法获得所有方法的结果。其实是可以的，但不能通过一次调用实现：必须遍历 [GetInvocationList] 返回的方法列表，并逐个调用。实际上，在多播委托中注册的方法大多返回 [void]。

// 我们定义一个 Operation 类型的对象，用来在其中注册方法
// 注册静态方法 Increase
Operation op = Calculations.Increase;
// 执行委托
int n = op(4, 7);
Console.WriteLine($"n={n}");

// 创建 Calculations 类型的对象 c1
var c1 = new Calculations();
// 把 c1 的 Add 方法注册到委托中
op = c1.Add;
// 执行委托对象
n = op(2, 3);
Console.WriteLine($"n={n}");
// 把 c1 的 Subtract 方法注册到委托中
op = c1.Subtract;
n = op(2, 3);
Console.WriteLine($"n={n}");

// 在委托中注册两个方法（多播委托）
op = c1.Add;
op += c1.Subtract;
// 执行委托对象：得到最后一个方法的结果
n = op(10, 4);
Console.WriteLine($"n={n}");
// 通过调用列表得到所有方法的结果
foreach (Operation method in op.GetInvocationList().Cast<Operation>())
{
    Console.WriteLine($"{method.Method.Name} -> {method(10, 4)}");
}
// 从委托中移除一个方法：结果可能为 null（Operation? 类型）
Operation? rest = op - c1.Subtract;
// 如果委托不为 null，则执行它
if (rest is not null)
{
    n = rest(1, 1);
    Console.WriteLine($"n={n}");
}
// 移除最后一个方法：委托变为 null
Operation? empty = rest - c1.Add;
Console.WriteLine($"empty is null: {empty is null}");
// ?.Invoke 仅在委托不为 null 时执行它
Console.WriteLine($"empty?.Invoke(1, 1)={empty?.Invoke(1, 1)}");

// 一个类，其方法具有 Operation 委托的签名
public class Calculations
{
    // 两个实例方法
    public int Add(int n1, int n2)
    {
        Console.WriteLine($"Add({n1},{n2})");
        return n1 + n2;
    }

    public int Subtract(int n1, int n2)
    {
        Console.WriteLine($"Subtract({n1},{n2})");
        return n1 - n2;
    }

    // 一个静态方法
    public static int Increase(int n1, int n2)
    {
        Console.WriteLine($"Increase({n1},{n2})");
        return n1 + 2 * n2;
    }
}

// 定义委托类型：一个方法模板

    委托是 不可变对象：运算 [+] 和 [-] （因此还有 [+=] 和 [-=]）并不修改现有的委托，而是创建一个新的委托。在处理事件时，这一特性将很重要。

    // 从匿名方法到 lambda 表达式

// 1 - 匿名方法（C# 2）：方法体直接写在原地
Func<int, int, int> add = delegate (int n1, int n2)
{
    return n1 + n2;
};
Console.WriteLine($"anonymous method: add(2, 3)={add(2, 3)}");

// 2 - 用 lambda 表达式（C# 3）实现同样的功能：参数 => 方法体
Func<int, int, int> subtract = (int n1, int n2) =>
{
    return n1 - n2;
};
Console.WriteLine($"block-bodied lambda: subtract(2, 3)={subtract(2, 3)}");

// 3 - 参数类型由目标委托类型推断
Func<int, int, int> multiply = (n1, n2) => n1 * n2;
Console.WriteLine($"expression-bodied lambda: multiply(2, 3)={multiply(2, 3)}");

// 4 - 单个参数：括号可省略
Func<int, int> square = x => x * x;
Predicate<string> isEmpty = s => s.Length == 0;
Console.WriteLine($"square(7)={square(7)}, isEmpty(\"\")={isEmpty("")}");

// 5 - 无参数：使用空括号
Func<string> greet = () => "Hello";
Action beep = () => Console.WriteLine("beep!");
Console.WriteLine(greet());
beep();

// 6 - 包含多条语句的块体
Action<string, int> repeat = (text, times) =>
{
    for (int i = 0; i < times; i++)
    {
        Console.Write(text);
    }
    Console.WriteLine();
};
repeat("ab", 3);

// 7 - 被忽略的参数（弃元）：不需要它们的值
EventHandler handler = (_, _) => Console.WriteLine("event received");
handler(null, EventArgs.Empty);

// 8 - 直接把 lambda 作为方法的参数传入
List<int> numbers = [3, 8, 1, 6, 5, 4];
Console.WriteLine($"even: {string.Join(" ", numbers.FindAll(n => n % 2 == 0))}");
numbers.Sort((n1, n2) => n2.CompareTo(n1));

    7.5. 事件处理

    7.5.1. .NET 事件模型

    委托用于定义事件。类 [C1] 可以按如下方式定义事件 [Evt1]：

    • 在类 [C1] 内部或外部定义一个委托类型：
    1
    delegate void Evt(T1 param1, T2 param2, ...);
    • 类 [C1] 定义一个该委托类型的字段：
    1
    public Evt? Evt1;
    • 当类 [c1] 的实例 [C1] 想要发出事件信号时，它会执行其委托 [Evt1]，并向其传递类型 [Evt] 所定义的参数。随后，注册在委托 [Evt1] 中的所有方法都会以这些参数执行。可以说它们收到了事件 [Evt1] 的通知；
    • 如果使用对象 [c1] 的对象 [c2] 想要收到对象 [c1] 的事件 [Evt1] 的通知，它就把自己的一个方法 [c2.M] 注册到委托 [c1.Evt1] 中。此后，每当对象 [c1] 上发生事件 [Evt1] 时，它的方法 [c2.M] 就会被执行。当它不再希望收到通知时，也可以取消订阅；
    • 由于委托 [c1.Evt1] 可以注册多个方法，不同的 [ci] 对象可以向 [c1.Evt1] 注册以获得事件通知。

    在这个场景中，我们有：

    • 一个发出（也称为“发布”或“触发”）事件的类；
    • 接收该事件通知的类。它们被称为订阅了该事件；
    • 一个委托类型，用于定义接收事件通知的方法的签名。这些方法称为事件处理程序。

    这就是观察者（Observer）设计模式：发出者并不知道其订阅者；它只是通知它们。

    .NET 框架为事件委托定义了标准签名：

    1
    public delegate void MyEventHandler(object? sender, EventArgs e);
    • [sender]：触发事件的对象；
    • [e]：类型为 [EventArgs] 或其派生类型的对象，提供有关事件的信息；
    • 按照惯例，委托类型的名称以 [EventHandler] 结尾。

    它还定义了在类中声明类型为 [MyEventHandler] 的事件的标准方式：

    字段 [Evt1] 属于该委托类型。关键字 [event] 限制了可以对其执行的操作：

    • 在类 [C1] 之外，只允许 [+=] 和 [-=] 操作。这可以防止其他对象覆盖或删除已订阅的方法（例如误将 [+=] 写成 [=]）。你只能订阅（[+=]）或取消订阅（[-=]）；
    • 只有类 [C1] 才能执行该委托，即触发事件：[Evt1?.Invoke(this, e)]。

    如果你试图在类外部写 [c1.Evt1 = null;] 或 [c1.Evt1(null, EventArgs.Empty);]，编译器会给出如下响应：[error CS0070: The event 'C1.Evt1' can only appear on the left hand side of += or -= (except when used from within the type 'C1')]。

    我们不为每个事件都定义一个委托类型，而是使用预定义的泛型委托：

    1
    public delegate void EventHandler<TEventArgs>(object? sender, TEventArgs e);

    类型 [TEventArgs] 是第二个参数的类型，即描述事件的对象。使用这个泛型委托，在类 [X] 中声明事件 [C] 时遵循下面推荐的模式：

    • 定义一个派生自 [XEventArgs] 的类型 [EventArgs] ，用于封装有关事件 [X] 的信息；
    • 在类 [EventHandler<XEventArgs>] 中定义一个类型为 [C] 的事件；
    • 在类 [C] 中定义一个受保护的虚方法 [protected virtual void OnX(XEventArgs e)] ，用于向订阅者发布事件 [X]。它是虚方法，以便派生类可以修改事件的发布方式。

    在 2008 年，类型 [TEventArgs] 必须派生自 [EventArgs] （约束 [where TEventArgs : EventArgs]）。这个约束在 .NET Framework 4.5 中被移除：任何类型都可以，包括 [record]。不过按照惯例，我们仍然派生自 [EventArgs]。请注意，[record] 不能派生自 [EventArgs]：[record] 只能继承另一个 [record]（错误：[CS8864: Records may only inherit from object or another record]）。因此我们将使用普通类。

public static class Tools
{
    // 用谓词过滤序列：相当于 Where
    public static IEnumerable<T> Filter<T>(IEnumerable<T> source, Func<T, bool> predicate)
    {
        foreach (T element in source)
        {
            if (predicate(element))
            {
                // 元素返回给调用者；迭代将从这里继续
                yield return element;
            }
        }
    }
}

public static class Extensions
{
    // IEnumerable<T> 的扩展成员（C# 14）
    extension<T>(IEnumerable<T> source)
    {
        // Filter 作为扩展方法：复用 Tools.Filter
        public IEnumerable<T> Filter(Func<T, bool> predicate) => Tools.Filter(source, predicate);

        // 转换每个元素：相当于 Select
        public IEnumerable<TResult> Transform<TResult>(Func<T, TResult> transformation)
        {
            foreach (T element in source)
            {
                yield return transformation(element);
            }
        }
    }
}

// 递归显示树节点及其子节点
static void Display(Expression node, int level)
{
    string margin = new(' ', 2 * level);
    switch (node)
    {
        case BinaryExpression binary:
            // 带两个操作数的运算：&&、>、==、%……
            Console.WriteLine($"{margin}{binary.NodeType}");
            Display(binary.Left, level + 1);
            Display(binary.Right, level + 1);
            break;
        case ParameterExpression parameter:
            Console.WriteLine($"{margin}Parameter {parameter.Name}");
            break;
        case ConstantExpression constant:
            Console.WriteLine($"{margin}Constant {constant.Value}");
            break;
        default:
            Console.WriteLine($"{margin}{node.NodeType} {node}");
            break;
    }
}

    这有什么用？委托只能在程序内部执行。而表达式树可以被解析并 翻译成另一种语言。Entity Framework Core 就是这么做的，我们将在第 11 章中探讨。当针对数据库表编写 LINQ 查询时，例如 [context.Brackets.Where(t => t.Limit > 20000)]，所使用的 [Where] 方法并不是 [IEnumerable<T>] 的方法，而是 [IQueryable<T>] 的方法，其参数是 [Expression<Func<T, bool>>]。EF Core 会像我们的 [Display] 方法一样遍历这棵树，并将其翻译成由数据库服务器执行的 SQL [WHERE limits > 20000] 子句。因此，同一个以相同方式编写的 Lambda，会根据其所接收参数的类型，变成 .NET 代码或 SQL 代码。

    7.8. 结论

    本章的要点：

    • 委托是引用一个或多个具有给定签名的方法的对象。预定义类型 [Func<>]、[Action<>] 和 [Predicate<T>] 通常使你无需定义自己的委托类型；
    • Lambda 表达式允许你在创建委托的地方直接编写方法。它们会捕获其周围的变量（要小心 [for] 循环）；
    • 委托可以取代只有一个方法的接口，并提供更大的灵活性；
    • 事件是受关键字 [event] 保护的委托：使用 [+=] 订阅，使用 [-=] 取消订阅，并且只有声明它的类才能使用 [Evt?.Invoke(this, e)] 触发它；
    • LINQ 建立在接受委托的方法之上，而 EF Core 建立在表达式树之上。
