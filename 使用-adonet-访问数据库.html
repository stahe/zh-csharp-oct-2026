    10. 使用 ADO.NET 访问数据库

    10.1. ADO.NET 连接器

    让我们回顾一下自第 6 章以来反复使用的分层架构。到目前为止，[Tax] 应用程序的 [dao] 层已经使用了三种类型的数据源：

    • 硬编码在代码中的数据（[HardwiredTax]）；
    • 来自文本文件的数据（[FileTax]）；
    • 来自 JSON 文件的数据（[JsonTax]）。

    在本章中，我们来研究数据来自数据库的情形。架构变为如下：

    在上图中，[dao] 层 [1] 通过一个特定于所用 DBMS 的类库 [2] 与 DBMS（数据库管理系统）[3]通信，DBMS 负责管理数据库 [4]。该类库实现了统称为 ADO.NET 的标准功能（ADO 是“ActiveX Data Objects”的缩写，是 Windows 上先于它出现的数据访问技术的名称）。它被称为“数据提供程序”或“连接器”。所有常见的 DBMS 都有 ADO.NET 连接器。

    连接器的类以 DBMS 命名：[MySqlConnection] 用于 MySQL，[SqlConnection] 用于 SQL Server，[NpgsqlConnection] 用于 PostgreSQL……如果 [dao] 层使用这些类，其代码中就包含连接器的名称，更换 DBMS 就需要修改它。这种架构既高效，因为针对特定 DBMS 编写的连接器可以充分利用该 DBMS；又僵化，因为更换 DBMS 需要修改 [dao] 层。第二点应当客观看待：企业并不会经常更换其 DBMS。此外，我们将看到，从 .NET 2.0 开始，ADO.NET 提供了一种“通用连接器”，在不牺牲性能的前提下提供了灵活性。

    2008 年的课程依次使用了 SQL Server Compact（已被 Microsoft 停止支持）、SQL Server 2005 Express、MySQL 5，然后是 ODBC 和 OLE DB 驱动程序，数据库是用 Visual Studio 向导创建的。这里我们使用单一的 DBMS，即 MySQL 8（附录中使用 Laragon 安装它），以及当今使用最广泛的 ADO.NET 连接器之一 MySqlConnector。数据库由 SQL 脚本创建，这些脚本通过 [mysql] 命令行客户端运行；附录还展示了如何使用 Laragon 附带的 HeidiSQL 图形客户端创建它们。

    10.2. 使用数据源的两种方式

    ADO.NET 允许以两种不同的方式使用数据源：

    • 连接模式；
    • 离线模式。

    在连接模式下，应用程序：

    • 打开到数据源的连接；
    • 以读/写模式使用数据源；
    • 关闭连接。

    在离线模式下，应用程序：

    • 打开到数据源的连接；
    • 将来自数据源的全部或部分数据的副本取回到内存中；
    • 关闭连接；
    • 使用内存中的数据副本，对其进行读取和写入；
    • 工作完成后，打开连接，将修改后的数据发送给数据源以便更新，然后关闭连接。

    离线模式依赖于 [DataSet] （一个小型内存数据库，包含其表 [DataTable]、行 [DataRow] 和关系）和 [DataAdapter]（[DataSet] 与数据库之间的桥梁）这些类。这些类在 .NET 10 中仍然存在，但在新应用程序中很少使用：对内存中的数据副本进行操作、随后保存更改的工作，现在由 ORM （“对象关系映射器”）来处理，它操作的是普通的 C# 对象，而不是表中的行。.NET 的 ORM Entity Framework Core是第 11 章的主题。与 2008 年的课程一样，我们在这里只关注连接模式，Entity Framework Core 正是基于该模式。

    10.3.2. SQL 语言的四条基本命令

    SQL（“Structured Query Language”，结构化查询语言）是一种部分标准化的、用于查询和更新数据库的语言。所有 DBMS 的方言都遵循 SQL 的标准化部分，但会添加专有的语言扩展，以利用其各自的特性。我们已经遇到过其中的两个例子：主键的自动生成，以及表的列所允许的数据类型，它们往往取决于 DBMS。

    我们在这里介绍的 SQL 语言的四条基本命令是标准化的，所有 DBMS 都支持：

    命令
    作用
    [select col1, col2, … from table1, table2, … where condition order by expression]
    用于从数据库中检索数据的查询。只有关键字 [select] 和 [from] 是必需的。对关键字 [from] 之后的所有表执行连接；只保留关键字 [select] 之后的列；只保留满足关键字 [where] 条件的行；所得的行按关键字 [order by] 中的表达式排序，构成查询的结果。这个结果是一张表。
    [insert into table(col1, col2, …) values (val1, val2, …)]
    向 [table] 中插入一行。[(col1, col2, …)] 指定该行中要用 [(val1, val2, …)] 中的值填充的列。
    [update table set col1=val1, col2=val2, … where condition]
    根据 [condition] 更新 [table] 中的行（如果没有 [where] 则更新所有行）。对于这些行，[coli] 列被设置为 [vali]。
    [delete from table where condition]
    删除 [table] 中与 [condition] 匹配的所有行（如果没有 [where] 则删除所有行）。

    10.3.3. 连接模式下 ADO.NET 的基类

    让我们回到通过 ADO.NET 连接器访问数据库的应用程序示意图：

    在连接模式下，应用程序：

    • 打开到数据源的连接；
    • 以读/写模式使用数据源；
    • 关闭连接。

    这些操作主要涉及三类对象：

    • 连接，它封装了数据库连接的属性和方法；
    • 命令，它封装了所执行 SQL 命令的属性和方法；
    • 数据读取器，它封装了 SQL [select] 命令的结果的属性和方法。

    每个连接器都定义了自己的类（MySqlConnector 的 [MySqlConnection]、[MySqlCommand]、[MySqlDataReader] ），这些类派生自所有连接器共有的抽象类，这些抽象类定义在 [System.Data.Common] 命名空间中：[DbConnection]、[DbCommand]、[DbDataReader]。2008 年的课程介绍的是 [IDbConnection]、[IDbCommand] 和 [IDataReader] 这几个接口，位于命名空间 [System.Data] 中，这些类实现了它们。如今更倾向于使用抽象类：它们比接口提供更多功能，而接口在不破坏现有连接器的前提下已无法再添加方法（当时还没有默认接口方法）。例如，方法的异步版本（[OpenAsync]、[ExecuteReaderAsync]、[ReadAsync] 等）只存在于抽象类中。

    10.3.3.2. DbCommand 类

    它用于执行 SQL 命令或存储过程。我们将使用的该类的方法 M 和属性 P 如下：

    名称
    类型
    作用
    [CommandType]
    P
    指定要执行的内容。其取值来自枚举 [CommandType]：[CommandType.Text] 执行属性 [CommandText] 中定义的 SQL 命令（这是默认值）；[CommandType.StoredProcedure] 执行数据库中的存储过程。
    [CommandText]
    P
    如果 [CommandType] 等于 [CommandType.Text]，则为要执行的 SQL 命令的文本；如果 [CommandType] 等于 [CommandType.StoredProcedure]，则为要执行的存储过程的名称。
    [Connection]
    P
    用于执行该 SQL 命令的连接 [DbConnection] 。
    [Transaction]
    P
    执行该 SQL 命令所在的事务 [DbTransaction] 。
    [Parameters]
    P
    参数化 SQL 命令的参数列表。命令 [update articles set price=price*1.1 where id=@id] 带有 [@id] 参数。
    [ExecuteReader]
    M
    执行 SQL [select] 命令。它返回一个 [DbDataReader] 对象，表示 [select] 的结果。
    [ExecuteNonQuery]
    M
    执行 SQL [update]、[insert] 或 [delete] 命令。它返回受该操作影响的行数（更新、插入、删除的行数）。
    [ExecuteScalar]
    M
    执行只返回单个结果的 SQL [select] 命令，例如 [select count(*) from articles]。

    10.3.7. 执行 SELECT 查询

    执行 SQL 命令包括以下步骤：

    • 连接到数据库；
    • 向数据库发送 SQL 命令；
    • 处理 SQL 命令的结果；
    • 关闭连接。

    第 2 步和第 3 步可以重复；只有在数据库处理结束时才关闭连接。打开的连接在 DBMS 中是有限的资源：必须节约使用，我们总是力求缩短打开连接的存续时间。在我们的程序中，每条 SQL 命令之后都会关闭连接，并为下一条命令打开一个新连接。

    然而，打开连接的代价很高：它需要与服务器建立网络连接，可能还要协商加密并进行身份验证。为了降低这一代价，连接器管理着一个连接池：当应用程序关闭连接时，连接器实际上并不关闭它，而是将其归还到池中；当应用程序使用相同的连接字符串打开新连接时，它会得到池中已经建立好的某个连接。这种机制的优点是对开发人员透明：无需修改程序即可使用它。在 MySqlConnector 中（与其他当前的连接器一样），连接池默认启用，并通过连接字符串参数（[Pooling]、[MaximumPoolSize]、[MinimumPoolSize] 等）进行配置。因此，最佳实践是在每个操作开始时打开连接，并在结束时使用 [using] 将其关闭。

    10.4.3. 应该选择哪个连接器？

    我们已经看到了使用 ADO.NET 连接器的两种方式：

    • 直接使用连接器的类：[dao] 层依赖于连接器。更换 DBMS 需要修改 [dao] 层；
    • 使用通用连接器：[dao] 层只认识抽象类和连接器的不变名称，而不变名称可以从配置文件中读取。

    因此，通用连接器似乎是理想的解决方案。但在实践中，它无法隐藏 DBMS 的所有具体细节：

    • 一旦超出基本命令，SQL 本身在不同 DBMS 之间就会有所不同：主键的生成、限制返回行数（MySQL 使用 [limit 10] ，SQL Server 使用 [top 10] 或 [offset … fetch] ）、列类型、日期函数等；
    • 参数化查询的参数语法各不相同：SQL Server、MySQL 和 SQLite 使用 [@name]，但 ODBC 和 OLE DB 驱动程序以及 2008 年的 MySQL 连接器使用 [?]（位置参数，没有名称），PostgreSQL 的原生 SQL 使用 [$1]、[$2] 等（Npgsql 也接受 [@name]）。对于位置参数，参数添加到 [Parameters] 集合中的顺序很重要；对于命名参数，顺序则无关紧要；
    • 最后，异常是 [DbException]，其错误代码取决于 DBMS。

    2008 年的课程提到了克服这些局限的框架：Spring.NET、iBatis.NET、NHibernate 和 LINQ to SQL。Spring.NET 和 iBatis.NET 已不再维护；LINQ to SQL 已不再开发，在当前的 .NET 中也不存在；NHibernate 仍然存在。如今，主要使用的是以下工具：

    • Entity Framework Core，Microsoft 的 ORM，将在第 11 章介绍：[dao] 层处理 C# 对象并用 LINQ 编写查询；生成特定于各个 DBMS 的 SQL 的是 EF Core；
    • Dapper，一个“微型 ORM”，为 ADO.NET 连接添加扩展方法，可将 [select] 的行直接转换为 C# 对象。我们仍然要编写 SQL，但不再需要编写遍历读取器的循环。

    这些工具都依赖于 ADO.NET 连接器：理解 ADO.NET 对于理解它们的工作方式以及排查它们的问题仍然很有用。

// 用参数化查询插入一个文章数组
static void InsertArticles(string connectionString, Article[] articles)
{
    using var connection = new MySqlConnection(connectionString);
    connection.Open();
    // 参数化查询：@name、@price、@cs、@ms 是它的参数
    const string Query = "insert into articles(name, price, currentstock, minimumstock) values(@name, @price, @cs, @ms)";
    using var command = new MySqlCommand(Query, connection);
    // 声明参数：名称和 SQL 类型
    command.Parameters.Add("@name", MySqlDbType.VarChar, 30);
    command.Parameters.Add("@price", MySqlDbType.Decimal);
    command.Parameters.Add("@cs", MySqlDbType.Int32);
    command.Parameters.Add("@ms", MySqlDbType.Int32);
    // 由 DBMS 准备（编译）查询
    command.Prepare();
    // 插入各行：只有参数的值在变化
    foreach (Article article in articles)
    {
        command.Parameters["@name"].Value = article.Name;
        command.Parameters["@price"].Value = article.Price;
        command.Parameters["@cs"].Value = article.CurrentStock;
        command.Parameters["@ms"].Value = article.MinimumStock;
        command.ExecuteNonQuery();
    }
    Console.WriteLine($"{articles.Length} article(s) inserted");
}

// 名称匹配 [like] 模式的文章
static List<Article> GetArticles(string connectionString, string pattern)
{
    using var connection = new MySqlConnection(connectionString);
    connection.Open();
    using var command = new MySqlCommand(
        "select id, name, price, currentstock, minimumstock from articles where name like @pattern order by id", connection);
    // 在一条语句中声明参数及其值
    command.Parameters.AddWithValue("@pattern", pattern);
    using MySqlDataReader reader = command.ExecuteReader();
    // 结果的每一行都变成一个 Article 对象
    List<Article> list = [];
    while (reader.Read())
    {
        list.Add(new Article(reader.GetInt32(0), reader.GetString(1), reader.GetDecimal(2),
            reader.GetInt32("currentstock"), reader.GetInt32("minimumstock")));
    }
    return list;
}

    10.6. 事务

    10.6.1. 概述

    事务是以“原子方式”执行的一系列 SQL 命令：

    • 要么所有操作都成功；
    • 要么其中一个操作失败，此时之前的所有操作都会被回滚。

    最终，事务中的所有操作要么全部成功应用，要么全部不应用。经典的例子是银行转账：从一个账户扣款和向另一个账户入账必须都完成，否则都不执行。当应用程序自己控制事务时，它使用 [COMMIT] 命令提交事务，或使用 [ROLLBACK] 命令回滚事务。

    在前面的示例中，我们没有使用事务。然而事务实际上是存在的，因为在 DBMS 中，SQL 命令总是在事务中执行。如果应用程序自己没有启动显式事务，DBMS 就会使用隐式事务。此时有两种情况：

    • 每条 SQL 命令都属于一个事务，该事务由 DBMS 在命令之前打开，并在命令之后提交。这称为自动提交模式。其行为就好像应用程序为每条 SQL 命令创建了一个事务；
    • DBMS 不处于自动提交模式：它在事务之外发出的第一条 SQL 命令时启动一个隐式事务，并让应用程序来结束它。之后的所有 SQL 命令都属于这个隐式事务，该事务可能因各种事件（连接关闭、启动新事务等）而终止，具体遵循 DBMS 特有的规则。应避免使用这种模式。

    默认模式由 DBMS 的配置决定。MySQL 在默认使用的 InnoDB 存储引擎下以自动提交模式运行。

    不同用户的命令在并行运行的事务中同时执行。一个事务所执行的操作可能会影响另一个事务所执行的操作。不同用户的事务之间有四种隔离级别：

    • 读未提交（Read Uncommitted）；
    • 读已提交（Read Committed）；
    • 可重复读（Repeatable Read）；
    • 可串行化（Serializable）。

    读未提交（Read Uncommitted）

    这种隔离级别也称为“脏读”（Dirty Read）。下面是在此模式下可能发生的一个例子：

    • 名为 U1 的用户在表 T 上启动一个事务；
    • 名为 U2 的用户在同一张表 T 上启动一个事务；
    • 用户 U1 修改了表 T 中的行，但尚未提交这些更改；
    • 用户 U2“看到”了这些更改，并根据所见做出决策；
    • 用户 U1 使用 [ROLLBACK] 回滚其事务。

    在第 4 步中，用户 U2 根据后来被证明是不正确的数据做出了决策。

    读已提交（Read Committed）

    这种隔离级别避免了前面的陷阱：在第 4 步中，用户 U2 不会“看到”用户 U1 对表 T 所做的更改。只有在 U1 使用 [COMMIT] 提交其事务之后，U2 才会看到这些更改。不过，在此模式下可能出现以下情况：

    • 用户 U1 在表 T 上启动一个事务；
    • 用户 U2 在同一张表 T 上启动一个事务；
    • 用户 U2 执行一条 [select] ，计算 T 中满足某个条件的行的 C 列的平均值；
    • 用户 U1 修改（[update]）T 的 C 列中的某些值，并提交更改（[commit]）；
    • 用户 U2 重复第 3 步中的同一条 [select] 。他们发现，由于 U1 所做的修改，C 列的平均值发生了变化。

    用户 U2 现在只能看到 U1 已提交的更改，但在同一个事务中，两次相同的操作却得到了不同的结果。这种情况称为“不可重复读”。对于想要获得表 T 一致视图的人来说，这是个问题。

    可重复读（Repeatable Read）

    在这种隔离级别下，只要用户停留在同一个事务内，就能保证从数据库读取到相同的结果。他们操作的是数据的一个“快照”，该快照不反映其他事务所做的更改，即使这些更改已经提交。只有在完成自己的事务之后，他们才会看到这些更改。

    从理论上讲，这种隔离级别还不够完美：另一个事务可能添加（[insert]）满足第 3 步中条件的行，这会改变后续读取的结果。这些行被称为“幻读”。这是 MySQL（InnoDB）的默认隔离级别，对于简单读取，它也能防止幻读。

    可串行化（Serializable）

    在这种隔离模式下，事务之间完全隔离：同时执行的两个事务的结果，与它们一个接一个地执行的结果相同。为实现这一点，DBMS 会锁定正在读取的数据，并使试图修改这些数据的事务等待（或失败）。这一级别会降低并行度，从而降低性能。

    并非所有 DBMS 都提供这四种隔离级别。默认隔离级别通常是 Read Committed（SQL Server、PostgreSQL、Oracle）或 Repeatable Read（MySQL）。应用程序创建事务时，可以显式指定该事务所需的隔离级别。

// 不使用显式事务插入一个文章数组
static void InsertArticlesOutOfTransaction(string connectionString, Article[] articles)
{
    using var connection = new MySqlConnection(connectionString);
    connection.Open();
    using MySqlCommand command = CreateInsertCommand(connection);
    foreach (Article article in articles)
    {
        InsertArticle(command, article);
    }
}

// 在事务内插入一个文章数组
static void InsertArticlesInTransaction(string connectionString, Article[] articles)
{
    using var connection = new MySqlConnection(connectionString);
    connection.Open();
    // 事务开始
    using MySqlTransaction transaction = connection.BeginTransaction(IsolationLevel.ReadCommitted);
    try
    {
        using MySqlCommand command = CreateInsertCommand(connection);
        // 命令必须在事务内执行
        command.Transaction = transaction;
        foreach (Article article in articles)
        {
            InsertArticle(command, article);
        }
        // 一切顺利：我们提交事务
        transaction.Commit();
        Console.WriteLine("transaction committed...");
    }
    catch (MySqlException ex)
    {
        // 某次插入失败：我们回滚事务
        transaction.Rollback();
        Console.WriteLine($"transaction rolled back ({ex.Message})");
    }
}

using System.Data.Common;
using System.Diagnostics;
using System.Runtime.CompilerServices;
using MySqlConnector;

const string ConnectionString = "Server=localhost;Port=3306;Database=dbarticles;User=root;Password=";

// 数据源：它为同一个数据库创建（已打开的）连接
await using var dataSource = new MySqlDataSource(ConnectionString);

try
{
    // 1 - 在事务内执行 update 语句
    await using (MySqlConnection connection = await dataSource.OpenConnectionAsync())
    {
        await using MySqlTransaction transaction = await connection.BeginTransactionAsync();
        await using var command = new MySqlCommand("update articles set price = price * 1.1 where price < @price", connection, transaction);
        command.Parameters.AddWithValue("@price", 200);
        int nbRows = await command.ExecuteNonQueryAsync();
        await transaction.CommitAsync();
        Console.WriteLine($"{nbRows} price(s) increased by 10 %");
    }

    // 2 - 一个 select，其行在读取时逐行返回
    await foreach (Article article in GetArticlesAsync(dataSource))
    {
        Console.WriteLine(article);
    }

    // 3 - 单个值
    await using (DbCommand command = dataSource.CreateCommand("select sum(price * currentstock) from articles"))
    {
        decimal stockValue = Convert.ToDecimal(await command.ExecuteScalarAsync());
        Console.WriteLine($"Stock value: {stockValue} euros");
    }

    // 4 - 被另一个事务阻塞的查询，一秒后被取消
    // [blocking] 事务修改 1 号文章且不结束：该行保持被锁定
    await using MySqlConnection connection1 = await dataSource.OpenConnectionAsync();
    await using MySqlTransaction blocking = await connection1.BeginTransactionAsync();
    await using (var command1 = new MySqlCommand("update articles set currentstock = currentstock - 1 where id = 1", connection1, blocking))
    {
        await command1.ExecuteNonQueryAsync();
    }
    // 另一个连接想修改同一行：它必须等待 [blocking] 事务结束
    using var cancellation = new CancellationTokenSource(TimeSpan.FromSeconds(1));
    var stopwatch = Stopwatch.StartNew();
    try
    {
        await using DbCommand command = dataSource.CreateCommand("update articles set price = price * 2 where id = 1");
        await command.ExecuteNonQueryAsync(cancellation.Token);
    }
    catch (OperationCanceledException ex)
    {
        Console.WriteLine($"{ex.GetType().Name} after {stopwatch.Elapsed.TotalSeconds:F0} s : {ex.Message}");
    }
    // [blocking] 事务没有被提交：[blocking] 被释放时它会被回滚
}
catch (MySqlException ex)

    using Entities;
using MySqlConnector;

namespace Dao;

// 从 MySQL 数据库读取税率档次的 [dao] 层
public class MySqlTax : ITaxDao
{
    // 此实现特有的错误代码
    public enum ErrorCodes { Access = 101, Data = 102 }

    // 默认查询：档次必须按限额递增的顺序返回
    public const string DefaultQuery = "select limits, coeffr, coeffn from brackets order by id";

    // 税率档
    public TaxBracket[] TaxBrackets { get; }

    // 构造函数：税率档次一次读取，一劳永逸
    public MySqlTax(string connectionString, string query = DefaultQuery)
    {
        List<TaxBracket> brackets = [];
        try
        {
            using var connection = new MySqlConnection(connectionString);
            connection.Open();
            using var command = new MySqlCommand(query, connection);
            using MySqlDataReader reader = command.ExecuteReader();
            // 结果的每一行对应一个档次：limit、coeffR、coeffN
            while (reader.Read())
            {
                brackets.Add(new TaxBracket(reader.GetDecimal(0), reader.GetDecimal(1), reader.GetDecimal(2)));
            }
        }
        catch (MySqlException e)
        {
            // 数据库访问错误：我们把它包装在 TaxException 中
            throw new TaxException("Error accessing the tax brackets database", e) { Code = (int)ErrorCodes.Access };
        }
        catch (Exception e) when (e is InvalidCastException or ArgumentOutOfRangeException)
        {
            // 缺少列、类型不正确的列或值为 NULL 的列
            throw new TaxException("The tax brackets of the database are incorrect", e) { Code = (int)ErrorCodes.Data };
        }
        // 空表也是一种错误
        if (brackets.Count == 0)
        {
            throw new TaxException("The database contains no tax bracket") { Code = (int)ErrorCodes.Data };
        }
        TaxBrackets = [.. brackets];
    }
}
    • 第 7 行：类 [MySqlTax] 实现了第 5 版的 [ITaxDao] 接口：一个只读的 [TaxBrackets] 属性（第 16 行）；
    • 第 10 行：此实现特有的错误代码，仿照 [FileTax] 和 [JsonTax] 的错误代码设计：101（2008 年课程中使用的代码）表示数据库访问错误，102 表示数据不正确；
    • 第 13 行：返回税率档次的查询。[order by id] 子句很重要：[business] 层要求税率档次按其上限升序排列，而不带 [select] 的 [order by] 返回行的顺序，SQL 并不保证（2008 年的查询遗漏了它）；
    • 第 19 行：构造函数接收连接字符串和查询，查询带有默认值（可选参数，C# 4）。与 2008 年的版本一样，税率档次在构造函数中 一次性 全部 读取 ：[dao] 层在应用程序中是单例，此后不再查询数据库。由于构造函数不能是异步的，读取操作使用 ADO.NET 的同步方法；

    using System.Data.Common;
using Entities;

namespace Dao;

// 从任意数据库读取税率档次的 [dao] 层
// 它只知道 ADO.NET 的抽象类：连接器由其工厂提供给它
public class DbTax : ITaxDao
{
    // 错误代码：与 MySqlTax 的相同
    public enum ErrorCodes { Access = 101, Data = 102 }

    // 税率档
    public TaxBracket[] TaxBrackets { get; }

    // 构造函数：连接器的工厂、连接字符串、返回税率档次的查询
    public DbTax(DbProviderFactory factory, string connectionString, string query)
    {
        List<TaxBracket> brackets = [];
        try
        {
            using DbConnection connection = factory.CreateConnection()
                ?? throw new InvalidOperationException("the connector cannot create a connection");
            connection.ConnectionString = connectionString;
            connection.Open();
            using DbCommand command = connection.CreateCommand();
            command.CommandText = query;
            using DbDataReader reader = command.ExecuteReader();
            while (reader.Read())
            {
                brackets.Add(new TaxBracket(reader.GetDecimal(0), reader.GetDecimal(1), reader.GetDecimal(2)));
            }
        }
        catch (DbException e)
        {
            throw new TaxException("Error accessing the tax brackets database", e) { Code = (int)ErrorCodes.Access };
        }
        catch (Exception e) when (e is InvalidCastException or ArgumentOutOfRangeException)
        {
            throw new TaxException("The tax brackets of the database are incorrect", e) { Code = (int)ErrorCodes.Data };
        }
        if (brackets.Count == 0)
        {
            throw new TaxException("The database contains no tax bracket") { Code = (int)ErrorCodes.Data };
        }
        TaxBrackets = [.. brackets];
    }
}

    10.11. 结论

    本章介绍了使用 ADO.NET 以连接模式访问数据库：

    • 特定于 DBMS 的 连接器 （MySQL 对应 MySqlConnector）提供类 [XxxConnection]、[XxxCommand]、[XxxDataReader]和 [XxxTransaction]，它们派生自 [System.Data.Common] 中的抽象类 [DbConnection]、[DbCommand]、[DbDataReader] 和 [DbTransaction]；
    • 连接要尽可能晚打开、尽可能早关闭，用 [using] 关闭：连接池使这种做法开销很小；
    • [ExecuteReader] 执行 [select] 并返回一个读取器，用 [Read] 逐行遍历；[ExecuteNonQuery] 执行 [insert]、[update] 或 [delete]，并返回被修改的行数； [ExecuteScalar] 返回单个值；
    • 错误是 [DbException] （对 MySqlConnector 而言是 [MySqlException] ）；
    • 外部值始终通过 参数传递，绝不拼接到查询文本中，这样可以防范 SQL 注入；
    • 事务 （[BeginTransaction]、[Commit]、[Rollback]）确保一系列命令是原子的 (SQL)；
    • 异步方法（[OpenAsync]、[ExecuteReaderAsync]、[ReadAsync]……）和 [await using] 是服务器应用程序中的标准做法；批处理 （[DbBatch]）减少与服务器的交互次数；
    • 通用连接器 （[DbProviderFactory]、[DbProviderFactories]）使代码独立于 DBMS，但受限于各 DBMS 自身的特性。

    [Tax] 应用程序的第 6 版表明，得益于分层架构，从文件切换到数据库只需编写新的 [dao] 层并修改配置。下一章将使用 Entity Framework Core 创建该层的第七个版本，由它自己生成 SQL 命令。
